# 小火車列表 Skill

美編貼一個商品網址，skill 讀那一頁，產最多 15 題問答（題目 20 字、回答 50 字），每題的題目和回答各放一個程式碼框。美編一題一題複製，貼進上架工具的「常見問題」。

## 11/18 第三版改了什麼

- 同事反映說明太長、不好懂。改成「給網址就產問答」：不先問問題，不問短名、題數、品類、HTML 版還是長條圖版。
- 不給帶入連結了，改成一題一題可複製的文字。美編在工具裡一格一格貼。
- 上架工具同一天改成只剩「常見問題」一區，可以新增，最多 15 題。比較、商品特色、固定題、規格、適用機型、商品摘要都拿掉了。
- 適用機型不由 skill 寫：有型號的商品，美編自己在工具加一題。
- 紅線字（9H、軍規、保固這類）不擋也不標，照網頁寫。
- 頁面讀不到時，請美編貼文字或傳截圖。原本「改成一題一題問美編」的做法拿掉了。

## 還沒驗過的

- claude.ai 自己打不打得開網頁。11/17 真測能讀到頁面，靠的是測試帳號電腦上的瀏覽器擴充功能。沒有擴充功能的美編帳號沒測過。讀不到的時候，skill 會請美編貼字或傳截圖。
- 讀圖。第三版 11/18 在 claude.ai 真測一次通過（品牌官網的手機殼頁，Claude App、Opus 5.5 中）：題數和字數守住，14 題都找得到頁面出處，框框可以一題一題複製。但那一頁的圖上沒有可寫的字，模型也說它只拿到圖的替代文字、看不到畫面。資訊寫在圖上的商品頁，第三版讀不讀得到還沒測。讀不到時，skill 會講哪裡讀不到，請美編貼字或傳截圖。
- 模型說它拿到的頁面文字是「整理過的版本」。照原文寫的規則，在這種情況下守不守得住，只測過一頁。

## 內含

- `SKILL.md`：流程、讀網頁的規則、寫法、輸出格式、交出前的檢查。zip 只放這一個檔。
- `check_questions.js`：對齊檢查，不進 zip。

第二版的 `reference/questions.md`（題目表）和 `reference/tone-rules.md`（語氣規則複本）第三版不用了，從資料夾拿掉。要找回來看 git 歷史。

## 怎麼試

在 Claude Code 從專案根目錄開對話，說：

> 照 `交付物/product-page/小火車列表/SKILL.md`，幫我做這個商品的小火車：（貼網址）

## 對齊檢查

`node check_questions.js`。對不上就列出來、exit 1。改了工具的字數上限、題數上限，或改了 SKILL.md，都要跑；打包 zip 前一定要跑。

它查的是：

- SKILL.md 的 `name` 和說明長度
- SKILL.md 寫的題數上限、題目字數、回答字數，跟上架工具 `gen.js` 的 `FAQ_MAX`、`LIMIT.faqQ`、`LIMIT.faqA` 一樣；有型號的商品寫到 `FAQ_MAX` 減 1 題就停（留一格給適用機型）
- SKILL.md 和這份 README 沒有內部用語（清單從 `上架工具/build.js` 的 `PRIVATE_WORDS` 讀），沒有破折號
- 第二版的東西沒有留著：帶入連結、`questions.md`、`tone-rules.md`、固定題
- 輸出格式那段還在：兩個框框的範例、第一行整句和最後一行。第一行講到的格子和按鈕名稱，在工具的 `train-form.js` 裡真的叫這個名字
- zip 裡的 `SKILL.md` 跟這裡的一樣。不一樣只印「!」提醒、不算失敗（改 SKILL.md 到打包之間本來就會不一樣），打包完要再跑一次看到「✓」

它不查的：

- 模型實際照不照規則做。要拿真的商品頁在 claude.ai 跑，對答案。
- 題目問得好不好。
