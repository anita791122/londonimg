# 小火車列表 Skill

問美編商品的問題，把回答寫成完整句子，輸出問答給上架工具用。

測試版只上過個人站（skill 頁的下載卡），還沒有發給同事。公司站沒有這個 zip。工具的「貼上 skill 給的問答」格子 11/2 拿掉了，問答只從帶入連結進工具。

## 兩種用法
- **美編自己回答**：一題一題問，字用美編的。原本的用法。
- **讀同款長條圖**（11/15 加，11/16 改成讀網址，見 SKILL.md 同名一節）：同款商品在別的賣場只有長條圖、沒有文字時用。美編只給網址，skill 自己打開那一頁，讀「商品規格」分頁的字和「商品特色」的圖。美編不用傳圖、不用貼規格；自己想傳或貼也照收。第一則只問三件事：長條圖版還是 HTML 版、短名、品類（題數、全名、兩個版本不問）。skill 讀完給一條帶入連結（第 2 版，`v=2`），不在對話裡交草稿表。美編點連結打開上架工具，每張卡下面有原文、出處和那張圖的網址，美編在工具裡按「對」「這款沒有」「不確定」，只有按「對」的卡會放進要複製的語法。報告區有「這次讀到」、先不放、還讀到的、讀不到的圖。有數字的卡、寫到別的牌子配件能不能用的卡，工具一開始放「不確定」。顏色和比較不從網頁寫，美編在工具裡自己填。事實照原文，字改成我們的講法。
  - 護欄：只開美編給的那一頁，不搜尋、不開別頁、不拿以前對話記得的內容補。圖只拿得到網址、看不到畫面，那張算讀不到，不從檔名、替代文字、網址猜。規格分頁讀不到記「讀不到」，不寫「沒有」。
  - 整頁打不開：講清楚，改成美編自己回答（照原本流程），不請美編傳圖。打得開但有些圖或規格分頁讀不到：讀到的照樣給連結，讀不到的寫在「這次讀到」和讀不到的圖，那些題目美編在工具裡自己填。
  - 為什麼改成讀網址：11/16 決定美編不用再傳一次圖，內容由美編勾過確認。11/15 那版要美編貼規格、一張一張傳圖，11/16 在 claude.ai 真測過一次，14 條過 13 條。
  - 為什麼核對搬進工具（11/16 流程改版）：對話裡逐列回「對」，回完就看不到原文了；在工具裡，原文和出處就在每張卡下面，沒按「對」的卡不會進語法，「格子填好了」不等於「做完了」。代價：美編在工具改字之後，skill 不會再對一次紅線（工具只比對字）；工具不存草稿，核對到一半重新整理就沒了；按鈕證明不了美編真的看過。
  - 工具要先上線，舊的工具看不懂第 2 版連結。工具 11/16 已經上個人站；這版 skill 的 zip 還沒推。
  - 連結下面一律再放一次同一條網址在程式碼框（11/17 加）。11/17 真測 B 在 claude.ai 網頁版，5236 字的連結畫成普通字、點不了；模型第 3 則多放了框框，複製貼到網址列，線上工具帶進 13 張卡，跟本機一致。為什麼點不了還沒驗（太長，或連結裡有 `|`、`;` 這兩個換字表沒列的字），所以先用框框保證打得開。
  - 圖網址是 `//` 開頭的，前面補 `https:` 再放（11/17 第 2 次改）。B 重跑時 momo 的圖網址開頭是 `//`（模型自己講的，沒有另外開頁面確認），照「不是 https 開頭的不放」，出處是圖的 13 張卡一張都沒有圖網址，工具裡就沒有「打開這張圖」。補完是 `https://img4.momoshop.com.tw/…`，跟上次 B 那輪真的點開過的圖網址同一個格式。`http:` 開頭的、抄不到的，還是不放。
  - 同一題用到的幾處講法相反，最後一行 `S：` 後面接「兩個出處講法不同，請對實際包裝。」（11/17 第 2 次改）。B 重跑的包裝卡：規格寫「附專用黏膠」，第 8、9 張圖寫「本產品僅含保護殼」，回答兩句都寫，卡片沒提醒。工具把 `S：` 整段放在卡片的「出處：」那一行，所以工具不用改。回答（`A：`）怎麼寫沒改。
  - 美編自己傳整張長圖：照讀，出處加「整張長圖，小字可能漏」。試讀時整張長條圖嚴格算只讀到 55%，一張一張是 38 項全對（1 頁、各 1 次）。11/13 照官方文件算過，切成 790×1500、重疊 150 px 就不會被縮小，之後要工具幫忙切，用這組數字。
  - 讀網址這版還沒驗過的，新真測要回答：
    - 打不打得開網頁，看的是那個對話有沒有會開網頁的瀏覽器工具（推論）。試讀時只貼網址讀規格，6 個對話讀到 2 個。有記到工具的那次，是一般對話用了瀏覽器工具，讀到藏在分頁後面的規格；無痕對話試了 4 個（3 種模型），都讀不到規格。都只跑 1 次。美編的對話有沒有這個工具，不知道。
    - 透過網址看圖準不準，沒對過答案。試讀時一般對話說它一張一張看了圖，但沒對答案卷。
    - 測試帳號有開記憶，舊的測試商品已經測過很多次。新真測要換一個沒測過的商品，不然分不出是讀到的還是記得的。

## 內含

- `reference/questions.md`：題目、問到第幾題、貼到工具哪一格
- `reference/tone-rules.md`：語氣規則，`londonimg-product/reference/tone-rules.md` 的複本。要改去改本尊，再複製過來
- `check_questions.js`：對齊檢查，不進 zip

## 題目有兩份，怎麼對齊
工具的固定題在 `上架工具/src/gen.js` 的 `TRAIN_Q`（畫面由 `src/train-form.js` 畫）。skill 的題目在 `reference/questions.md`。

做法是一支檢查：`node check_questions.js`。對不上就列出來、exit 1。下面這些事之後要跑，打包 zip 前也一定要跑：
- 改了 `TRAIN_Q`、選項、字數門檻
- 改了語氣規則（`tone-rules.md`）
- 改了提醒字清單（`seo-geo-rules.md` §6）

它查的是：
- 工具的固定題：問句一字不差，選項都在。skill 自己加的題目 id 用 `c-`／`o-` 開頭，問句不跟固定題撞
- 品類表：每列剛好 3 題，都是問句，不跟其他商品那 7 題撞。碰到電池、發熱、行車、搭機的題（比對飛機、燙、邊充邊用、開車這幾個字）要標「有公司資料才答」，SKILL.md 要有這條規則
- 題數：手機殼每一級 5 題，重量厚度在最少的 5 題裡，其他商品寫的題數對得上
- 紅線字：比較和特色、手機殼、其他商品、品類表，四張表的題目都掃。§6 的字從規則檔讀，其他的（通過、保固、背板、聚碳酸酯、PC、9H、變黃、跌落、公尺、價格、出貨、到貨這類）列在這支裡
- 數字：從 SKILL.md、questions.md 讀出太短門檻、回答、問題、比較的字數和特色項數，跟工具的常數比。那句被改寫到讀不到，也算對不上
- 追問表第一欄跟工具 `YES_ONLY` 逐字比，兩邊都不能多
- 語氣規則和 §6 一樣，沒有內部用語和破折號
- 測出洞才加的規則還讀得到，語氣字清單兩處一致，定案商品名 6 款
- SKILL.md 的問答範例丟進工具的 `trainImport` 拆得開
- 帶入連結：第 5 段在，網址開頭只有一處，換字表齊全，範例連結丟進工具解開要等於第 4 段的範例
- 讀同款長條圖：〈流程〉開頭有分流那句，這一節的規則字都在，照抄的那幾段在引用框裡，舊的草稿表做法沒有留著，特色的上限和下限跟工具一樣，開頭那段有「網頁只開美編給的那一頁」
- 讀網頁的連結（第 2 版）：規則字都在；品類代號表跟工具的品類一樣、名字跟 questions.md 品類表一樣；範例連結丟進工具 `trainFromLink`，要解得開、品類放進去、原頁網址的 `&` 換回來、每張卡有原文和出處、有一張帶圖網址、數字卡預設不確定、沒有一張一進來就是「對」、還沒核對的卡不進語法，T、X、R、I 四種行都有示範到；連結下面要附程式碼框的規則字都在，程式碼框格式那一行等於連結格式小括號裡那一段（11/17）

它不查的：
- 紅線字的同義說法：這支只比列出來的字，新的講法要自己加進去
- 題目問得好不好，哪些題算安全題（這支只比那幾個字）
- SKILL.md 的追問句、紅線句、例子句寫得對不對，例子有沒有多寫字
- 模型實際照不照規則做：這支只看文字還在不在，要另外跑劇本
- 模型打的連結有沒有錯字：要另外跑劇本，解開逐字對第 4 段（讀網頁時，對它寫的卡）
- 讀網頁的連結：模型抄的圖網址是不是那一張圖、點不點得開，要拿真的頁面跑
- 讀同款長條圖：模型讀頁面、讀圖讀得對不對，改寫有沒有多寫事實，有沒有搜尋或開別頁。要拿真的頁面在 claude.ai 跑，對答案卷
- 定案商品名跟專案的命名紀錄有沒有一致：這支只數款數，改名時要自己改
